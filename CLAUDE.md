# Repository conventions

## Ownership

I author and am responsible for all code in this repo, including changes
made with AI assistance. Never attribute authorship, generation, or
co-authorship to Claude, Cursor, or any other tool: not in commits,
branch names, PR titles or descriptions, PR comments, code comments, or
any other repo content. No "Generated by Claude Code" footers, no
`Co-Authored-By: Claude` trailers, no session links.

## Git: I commit

- Never run `git commit`, `git push`, or `git add` for the purpose of
  committing unless I explicitly ask in that message.
- "Implement the plan", "fix this", or "apply the changes" does not mean
  commit.
- After making changes, leave them uncommitted and say what I should
  review.
- If I ask for a commit message, provide the text only.
- Do not push, open a PR, or rewrite pushed history unless explicitly
  asked.
- Before handing off a commit, run `git log -1 --format='%an <%ae>'` and
  confirm the author is me, not a tool identity.

## Branch naming

Never prefix branches with `claude/`, `cursor/`, or any other tool name.
Use `feature/`, `fix/`, `chore/`, `docs/`.

## Commit messages

One line, lowercase, imperative mood, no type prefix — matching this
repo's existing history. ~72 characters, no body.

## Pull requests

- Base branch is `master`. Merge commits, not squash or rebase.
- Explain what a reviewer cannot see from the diff alone.
- Never state the obvious or restate my request back to me.
- After creating or updating a PR, read the body back from the GitHub
  API and confirm no footer or session link was appended; strip it with
  a follow-up update.
